### 01.1 — Repository & app structure

**What & why.** Stand up the Vite + React + TypeScript app (ADR-002) with a layout that makes the two
seams (ADR-003, ADR-004) physically obvious — a reviewer should be able to tell from the directory
structure alone that `src/server/` is the only place secrets and the data seam may be touched.

**Value archetype.** Enabler — gates every later story in both epics.

**Architecture alignment.** [`architecture/00-overview.md`](../../architecture/00-overview.md) (system
diagram), ADR-002 (stack), ADR-003/ADR-004 (the two seams this layout must make visible).

**Target (end goal).** A conventional, strict-typed Vite+React+TS app: `src/app/` for client UI
(scenes, motion, components), `src/server/` for the two API-route handlers and everything behind the
seams (`src/server/data/` for `LeadsRepository`), `src/shared/` for types/schemas both sides import
(e.g. the `Result<T>` type, zod schemas). ESLint + Prettier + strict `tsconfig`. Vitest wired and
running (even with zero tests yet).

**This increment.** Exactly the target — nothing pragmatic to cut at this size. Scaffold via
`npm create vite@latest . -- --template react-ts` adapted to the layout above, add
`vercel.json`/`api/` per Vercel's serverless-function convention (Vite's `api/*.ts` routes deploy as
functions automatically — no extra config beyond the function files themselves), configure ESLint +
Prettier + Vitest, add `Result<T>` in `src/shared/result.ts`.

**Path to target.** Increment == target.

**Decisions raised.** None beyond ADR-002 (already recorded).

**Debt incurred.** None.

**Open-questions check.** No blockers.

**Acceptance criteria.**
- `npm run dev` serves the app locally; `npm run build` produces a static build.
- `npm run typecheck` (strict mode), `npm run lint`, and `npm run test` all exist as scripts and pass
  (test passes vacuously with zero tests).
- Directory layout matches the target: `src/app/`, `src/server/` (with `src/server/data/` reserved for
  the seam), `src/shared/`, `api/` for the two serverless functions.
- `src/shared/result.ts` exports the `Result<T>` type used by CLAUDE.md §6.
- README's tech section points at `architecture/00-overview.md` rather than restating it.

#### QA round 1 — 2026-09-11: FAIL

Independent review (Opus subagent) found Phase 2 fully green (all five acceptance criteria met,
observed directly — dev server, build, typecheck, lint, test, `board:check`, `check:links`) but failed
Phase 1 compliance on three unlogged findings, against this story's own "Debt incurred: None":

- **F-1** — `api/` and `src/server/` were typechecked and linted under the *client's* DOM-typed
  project, contradicting the story's stated goal that the structure alone should make the seam
  obvious. A server handler using `document`/`window` would have typechecked and linted clean.
- **F-2** — `vitest run`'s default include glob swept up `scripts/board-check.test.mjs` (a `node:test`
  file belonging to the framework scaffold); Vitest reported it as a silent `(0 test)` pass regardless
  of its real result — a false-green risk in a brand-new harness.
- **F-3** — ADR-003/ADR-004's seam invariants (nothing outside `leadsRepository.ts` imports Supabase;
  the client never imports `src/server`) had zero mechanical enforcement, catchable only by human
  review.

**Round hygiene:** recorded here per `tech-qa` SKILL.md before round 2, so the open PR reads as
gated-and-failed rather than never-gated.

#### Build round 2 — 2026-09-11 (post-QA fix)

All three findings fixed directly on this same branch (not deferred as debt — cheap to fix at this
size and this is the story that establishes the seams):

- **F-1** — split the single `tsconfig.app.json` into `tsconfig.base.json` (shared strict options) +
  `tsconfig.app.json` (`src/app`, `src/shared`; DOM lib) + `tsconfig.server.json` (`src/server`,
  `api/`, `src/shared`; no DOM, `types: ["node"]`). `typecheck` now runs both projects plus
  `tsconfig.node.json`.
- **F-2** — `vite.config.ts` test config now sets `test.include: ["src/**/*.{test,spec}.{ts,tsx}"]`,
  scoping Vitest to this app's own tests; dropped the now-obsolete `passWithNoTests`.
- **F-3** — `eslint.config.js` reorganized into per-area blocks (`src/app/**`, `api/**` +
  `src/server/**`, `src/shared/**`, tests, root configs) with `no-restricted-imports` enforcing both
  seams: client code cannot import `@server/*`/`src/server/*` or `@supabase/supabase-js` directly; only
  `src/server/data/leadsRepository.ts` is exempted from the Supabase-import ban. Verified live by
  temporarily adding a Supabase import under `src/app/` and confirming ESLint rejects it with the
  ADR-003 message, then removing the probe file.

Re-ran `typecheck` / `lint` / `test` / `build` after the fix — all green. Ready for QA round 2.
