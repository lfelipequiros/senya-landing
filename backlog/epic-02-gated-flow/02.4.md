### 02.4 — Scene 2 — the code gate & the glitch

**What & why.** The scene that makes the list worth having. A single shared access code — distributed
through the brand's own channels — is what separates an invited visitor from a passer-by. Correct code
advances to the form in place; **wrong code ends the run**: the page glitches out and offers one button,
which reloads everything back to scene 1.

The gate is not primarily a security mechanism — one shared code stops nobody determined. It is a
**social** mechanism: it makes entry feel earned, and it makes the resulting list a list of people who
were actually invited.

**Value archetype.** Brand perception (the gate and its failure state are the product's strongest
statement) + Acquisition (it qualifies who reaches the form).

**Surface / UX fit.** State 2 of the single surface, and the last URL-reachable one. Establishes
[PDR-001](../../product/decisions.md) — failure is theatrical and terminal, not forgiving — which every
later error state in this product must stay consistent with.

**Prioritization.** After 02.1–02.3. The glitch treatment itself comes from 02.2 rather than being
invented here.

> **Product-check concern — raised, overridden, retained.**
> A full glitch plus full reload punishes a **typo** exactly as hard as it punishes someone with no
> code. On a phone keyboard, one mistyped character costs the visitor the entire opening animation
> again — and because the experience is stateless ([PDR-002](../../product/decisions.md)), a second
> typo costs it a third time. The realistic failure mode is an *invited* visitor rage-quitting before
> reaching the form, which is an acquisition loss with no acquisition upside.
> Three softer resolutions were offered — a skippable replay on the second pass, reloading to the gate
> instead of scene 1, and a "no code?" lead-recovery capture — and the owner **rejected all three**:
> the penalty is the brand statement. Recorded here so `tech-planning` and `tech-build` inherit the
> reasoning rather than rediscovering the tension, and so the trade is a known one if signup numbers
> later come in low. **Do not silently soften this during build** — it is a decided product position,
> and changing it is a product decision, not an implementation one.

**Edge cases — resolved.**
- **Wrong code.** Full-page glitch → single reload button → full replay from scene 1. No inline retry,
  no attempt counter, no lockout, no hint.
- **Empty submission.** Treated as a wrong code. No special-casing — consistent with the terminal stance.
- **Whitespace / casing / autocorrect.** Normalized before comparison. A phone that capitalizes the
  first letter or appends a space must not trigger the glitch — that is a platform artifact, not a wrong
  answer, and glitching on it would be indefensible.
- **No code at all.** Same terminal path. Lead recovery explicitly rejected (see the epic README).
- **Reduced motion.** The glitch still happens and is still terminal, expressed through 02.2's calmer
  vocabulary — a reduced-motion visitor must not get a *different* outcome, only a different rendering.
- **The code itself.** A secret, not a literal in the source — it is configuration, owned by
  [01.3](../epic-01-foundation/01.3.md).

**Edge cases — deferred.**
- Considered, deferred — rate limiting the code check against scripted guessing. Tracked at epic level
  as a launch-blocker; resolve in this story's `tech-planning` pass or in 02.7.
- Considered, deferred — rotating or revoking the code without a deploy. Acceptable while there is one
  drop and one code.

**Acceptance criteria (product-level).**
- Scrolling from the opening reveals the code input as its own scene.
- The correct code advances to the form in place, with no page change.
- A wrong or empty code produces the full glitch and a single reload control, which restarts the run
  from scene 1.
- Casing, surrounding whitespace, and mobile autocorrect artifacts do not cause a false rejection.
- The code is read from configuration and appears nowhere in client source.
- Under reduced motion, a wrong code is still terminal and still legible as a failure.
